<objective>
Close UAT Gap 3 (cosmetic): the Input error message on `/design-system` renders in body navy (`--color-text` = `oklch(0.225 0.044 264.6)`) instead of a visually distinct error color. Code matches Plan 24-02 verbatim (lines 28, 220, 297 mandated "no red" because the v2 @theme has no danger token). The v2 token system defines exactly 8 color tokens (`primary`, `primary-hover`, `surface`, `surface-muted`, `text`, `text-muted`, `border`, `accent`) — no `--color-danger`/`--color-error`/`--color-red`. Differentiation currently relies on `aria-invalid="true"`, `role="alert"`, and a `⚠` glyph alone — visually weak and below the user's UAT expectation.

This is a SPEC-LEVEL gap, not just a code bug. The fix is to PROMOTE a 9th token (`--color-danger`) into the v2 contract:

1. Declare `--color-danger: oklch(0.50 0.22 27)` (≈ #b91c1c — WCAG-AA-passing baseline, ≈ 5.5:1 contrast against white at 14px body text). Include a darken ladder in the comment (0.50 → 0.45 → 0.40 → 0.35) so the executor can escalate to a darker shade if axe-core color-contrast fails at the baseline.
2. Sweep `src/pages/design-system.json.ts` lines 50-55: the spacing object still references `--space-xs/sm/md/lg/xl/2xl`, stale from commit 8932a76's rename to `--spacing-*`. Fix all six entries to `--spacing-{size}` in the same JSON-touching pass (this is a pre-existing latent defect — `/design-system.json` currently misreports the spacing cssVar names; correcting it here is cheaper than a separate plan).
3. Wire the new token into the design-system page (`colorTokens` array → 9th swatch) and the JSON endpoint (`colors.danger` entry).
4. Change `src/components/v2/ui/Input.astro:56` from `text-text` to `text-danger`.
5. Update `24-UI-SPEC.md` at three referenced locations (~98, ~257, ~333) so the SPEC reflects the closed gap, not the deferred one.
6. Add a Playwright assertion that catches future regressions: the error <p>'s computed color must be red-dominant (R > G, R > B, R ≥ 120) AND must NOT be `rgb(20, 31, 57)` (the deterministic Chromium conversion of `--color-text` — the broken state). The existing axe-core test is the hard WCAG gate; the new assertion is the targeted red-ness guard.

Purpose: severity is cosmetic but the gap is permanent and propagates to every downstream form (Phase 28 contact form, future newsletter signup, etc.). Closing it now with a token-level fix means every consumer of `text-danger` (or `bg-danger`, `border-danger`, etc. as Tailwind v4 auto-generates the family) gets the right behavior for free. The stale-reference sweep on the JSON endpoint is a Plan-24-03-style "fix it while you're there" pre-existing-bug close.

Output: 6 modified files — `src/styles/v2/global.css` (1 token line + 6-line comment added inside @theme), `src/pages/design-system.json.ts` (1 colors entry added + 6 spacing-cssVar sweeps), `src/pages/design-system.astro` (1 colorTokens entry added), `src/components/v2/ui/Input.astro` (1-utility swap on line 56), `24-UI-SPEC.md` (3 surgical line edits), `tests/accessibility/v2-primitives.spec.ts` (1 new test appended inside existing describe block).
</objective>
