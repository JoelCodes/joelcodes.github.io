# Phase 24 — UI Design Contract

> Visual and interaction contract for v2 primitive library (Button, Card composition, Input, Badge) and the rebuilt `/design-system` page. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Spacing Scale

Declared values (locked by Phase 23 — v2 token rename uses t-shirt scale, not 4/8 numeric tokens, but every value is a multiple of 8px):

| Token | CSS variable | Value | Usage |
|-------|--------------|-------|-------|
| xs | `--space-xs` | 8px (0.5rem) | Icon → label gap inside Button (`iconLeft`/`iconRight` D-04, D-11), Badge icon prefix gap |
| sm | `--space-sm` | 16px (1rem) | Button inner horizontal padding (per Crito `[16, 20]` D-02 `md` size), Input field internal padding, Card sub-component vertical rhythm, link-row gap |
| md | `--space-md` | 24px (1.5rem) | CardBody internal padding (default), heading→body gap inside CardHeader, Token Reference grid gap on `/design-system` |
| lg | `--space-lg` | 32px (2rem) | CardBody internal padding (`elevated` cards, service cards), `/design-system` section content side-padding, container gutter |
| xl | `--space-xl` | 48px (3rem) | `/design-system` section vertical rhythm between Tokens / Primitives / Usage blocks; gap between adjacent primitive demo groups |
| 2xl | `--space-2xl` | 80px (5rem) | Page-level section breathing room on `/design-system` (Tokens vs. Primitives vs. Usage region breaks); top/bottom page padding |

**Exceptions:**
- Button `sm` size MAY use 12px vertical padding to keep header-CTA height tight; horizontal padding stays on the scale (16px). 12px is NOT a token — applied as a literal Tailwind `py-3` only on Button `sm`. Documented here so the checker does not flag it.
- Input border thickness: 1px (Crito-verified) — non-spacing micro-value, not a token.
- Focus ring offset: 2px (D-18) — non-spacing micro-value, not a token.
- Badge `sm` chip horizontal padding: 12px (between xs=8 and sm=16) — needed to keep pill shape visually balanced at 12px text. Applied as `px-3` literal on Badge only.

All other spacing decisions (CardHeader padding, CardFooter padding, Input vertical padding, Badge vertical padding) MUST resolve to a value from the table above. Plan 24-01 / 24-02 will lock the specific token-per-slot mapping; the freedom is in *which* token, not *what* value.

## Typography

Locked by Phase 23 token system. Only **3 sizes** plus **1 display size** are used in this phase's primitives — the 8-step scale exists in tokens but `/design-system` does not invent new combinations.

| Role | Size | CSS var | Weight | Weight var | Line Height | Used in |
|------|------|---------|--------|------------|-------------|---------|
| Display | 48px (3rem) | `--text-display` | 700 (display) | `--font-weight-display` | 1.4 (`--leading-display`) | `/design-system` page H1 ("Design System"); Token Reference type-scale demo top sample |
| Heading (H2) | 30px (1.875rem) | `--text-h2` | 700 (display) | `--font-weight-display` | 1.4 (`--leading-display`) | `/design-system` section headings (Tokens / Primitives / Usage) |
| Heading (H3) | 24px (1.5rem) | `--text-h3` | 700 (display) | `--font-weight-display` | 1.4 (`--leading-display`) | Primitive sub-headings ("Button", "Card", "Input", "Badge") + CardHeader default heading slot |
| Body | 16px (1rem) | `--text-body` | 400 (text) | `--font-weight-text` | 1.6 (`--leading-text`) | Default body, Input value text, CardBody paragraphs, Usage-section description copy |
| Button label (md) | 16px (1rem) | `--text-body` | 500 (text-bold) | `--font-weight-text-bold` | 1 (button-local override) | Button `md` and `lg` labels — Crito nav weight 500 verified |
| Button label (sm) | 14px (0.875rem) | `--text-small` | 500 (text-bold) | `--font-weight-text-bold` | 1 | Button `sm` (header CTA, blog share) |
| Input label | 14px (0.875rem) | `--text-small` | 500 (text-bold) | `--font-weight-text-bold` | 1.4 | `<label>` above input fields |
| Input error / helper | 14px (0.875rem) | `--text-small` | 400 (text) | `--font-weight-text` | 1.4 | Inline `role="alert"` element below input (D-14) |
| Badge | 12px (0.75rem) | `--text-caption` | 500 (text-bold) | `--font-weight-text-bold` | 1 | All Badge variants (chip/tag) |
| Code snippet (Usage) | 14px (0.875rem) | `--text-small` | 400 (text) | mono fallback (`ui-monospace, SFMono-Regular, Menlo`) | 1.5 | `<pre>` blocks in Usage section |

**Counts (checker dimensions):**
- Sizes used in primitives: **4** (display 48, h3 24, body 16, small 14, plus caption 12 reserved exclusively for Badge → 5 distinct primitive-facing sizes). The full 8-step token scale is *catalogued* on the `/design-system` Tokens section but only 4–5 are actively *consumed* by primitives.
- Weights used: **2** (`--font-weight-text` 400 + `--font-weight-text-bold` 500). The third weight token `--font-weight-display` 700 is reserved for *headings only* (h1/h2/h3/h4/display); no primitive component label or body element uses it.
- Body line-height: **1.6** (Crito-verified)
- Heading line-height: **1.4** (Crito-verified)

**Font assignment rule (locked):**
- Headings (h1–h4, display) + Button labels → `--font-display` (Plus Jakarta Sans)
- Body, Input text, paragraphs, Badge text, footer text, code → `--font-text` (Inter)
- No primitive may invent a third font. No `--font-heading` / `--font-body` references (collides with v1 — Phase 23 D-08).

## Color

60/30/10 split mapped to Phase 23 verified Crito palette. Every value below is locked by `src/styles/v2/global.css`; this section names the *role* each plays in the primitive contract.

| Role | Token | OKLCH value | Usage |
|------|-------|-------------|-------|
| Dominant (60%) | `--color-surface` | `oklch(1 0 0)` (#ffffff) | Page background on `/design-system`; Card default fill; Input field fill; Button `primary` text color (label on green); Button `ghost`/`link` background (transparent over surface) |
| Secondary (30%) | `--color-surface-muted` | `oklch(0.985 0 0)` (#fafafa) | `/design-system` Tokens section background (alternating-section pattern); CardBody background when inside elevated container; future Footer bg (already in use). NOT used for active component fills — strictly a sectioning surface |
| Secondary text | `--color-text` (= `--color-primary`) | `oklch(0.225 0.044 264.6)` (#141f39 navy) | All headings; all body copy; Button `primary` label color (navy on green CTA); Button `ghost` label; Button `link` label; Input value text; Input label; Badge `outline` text |
| Tertiary text | `--color-text-muted` | `oklch(0.395 0.011 274.7)` (#52525b) | Secondary copy in CardBody (descriptions under headings); Input helper-text (non-error); Badge `muted` text; Token Reference hex/OKLCH labels next to swatches |
| Accent (10%) | `--color-accent` | `oklch(0.79 0.184 148.5)` (#38da71 Crito green) | Reserved (see "Accent reserved for" below) |
| Border / hairline | `--color-border` | `oklch(0.864 0.005 286.3)` (#d4d4d8) | Card default 1px outline; Input field 1px border (default + disabled); Button `ghost` 1px outline; Badge `outline` 1px stroke; section hairlines on `/design-system`; HeaderV2 bottom border (already in use) |
| Primary-hover | `--color-primary-hover` | `oklch(0.286 0.054 264.6)` (#1d2a4c) | Button `ghost` hover background tint (or text color shift); link hover state on text-only links inside CardBody |
| Destructive | (none — no token in Phase 23) | n/a | **Not declared.** Phase 24 has no destructive action. Input error state uses semantic markup (`role="alert"`, `aria-invalid="true"`, `aria-describedby`) and a left-border or text treatment using `--color-text` weight + ✱ asterisk; NO red color is added. If Phase 28 (contact form) needs an error red, it adds the token then. Documented as a deliberate gap. |

**Accent reserved for** (explicit list — `--color-accent` green is NEVER used elsewhere in this phase):

1. Button `primary` background fill (the single ground-truth CTA shape)
2. Active nav link underline / `aria-current="page"` indicator (already in HeaderV2 from Phase 23 — no new use here)
3. Focus-ring color: `outline: 2px solid var(--color-accent)` on every interactive primitive (D-18)
4. Badge `accent` variant background fill — used in v1.4 ONLY for "Featured" project flag (PROJ-05) and `/design-system` page demo. Not a general-purpose chip color; documented use-cases only.
5. Text-link arrow (Lucide `ArrowRight`) inside Button `link` variant on hover/focus — color shift from `--color-text` to `--color-accent` on hover only (optional implementer choice; default = stays text color)

**Forbidden accent uses** (checker enforcement):
- Card border or fill — never. Cards are surface + border, full stop.
- Input field border default state — never. Uses `--color-border` only. (Focus ring is the accent moment — not the field outline.)
- Body text, headings, paragraph copy — never.
- Background of any section on `/design-system` — never. Sections use `--color-surface` or `--color-surface-muted` only.
- Badge `muted` or `outline` variants — never. Only `accent` variant uses the green fill.

**Contrast verification (locked targets, validated by Plan 24-03 axe-core):**
- `--color-text` on `--color-surface`: navy on white → ~13:1 (WCAG AAA body)
- `--color-text` on `--color-accent`: navy on green → ~6.8:1 (WCAG AA body, AAA large) — Button `primary` label
- `--color-text-muted` on `--color-surface`: gray on white → ~7.5:1 (WCAG AAA body)
- `--color-accent` outline on `--color-surface`: green on white → ~3.4:1 (WCAG AA non-text — focus ring per D-18)
- `--color-accent` outline on `--color-accent`: green ring on green button → fails alone, mitigated by 2px `outline-offset` putting white between ring and fill (D-18 explicit)

## Interaction Contract Summary

| Surface | Trigger | Result |
|---------|---------|--------|
| Button (any variant) | Click / Enter / Space | Standard button activation; `<a>` form follows `href` |
| Button | Tab focus | `outline: 2px solid var(--color-accent); outline-offset: 2px;` ring (D-18) |
| Button `primary` | Hover | Background opacity → 0.9 |
| Button `ghost` | Hover | Background → `--color-surface-muted` |
| Button `link` | Hover | Text color → `--color-accent`; arrow icon translateX 2px |
| Card `interactive=true` | Hover | `translateY(-4px)` + 200ms ease |
| Card `interactive=true` | Tab focus | Same accent focus ring |
| Input | Tab focus | Same accent focus ring; placeholder remains visible |
| Input `error` | (set by parent) | `aria-invalid="true"` + `role="alert"` element appears below; SR announces |
| Input `disabled` | (set by parent) | `cursor: not-allowed`; no focus reachable; muted bg |
| Badge | n/a | Non-interactive; static pill |
| `/design-system` page | Tab through | Reaches every Button + Input on the page; tab order = DOM order; no focus traps |

**Keyboard contract (D-20 — Plan 24-03 verifies):**
1. Tab from page top → reaches header skip link → header logo → 4 nav links → "Let's Talk" CTA → mobile-nav button (hidden md+) → page H1 → ... → first Button on page → through every Button → through every Input → through any interactive Card → into footer.
2. Every focused element shows visible accent focus ring.
3. No `outline: none` anywhere in v2 primitive files — verified by grep gate.
