## Decisions Made

**1. Shadow token promoted to v2/global.css (resolves CONTEXT Claude's Discretion)**

Decision: Option (a) — token promotion. Added `--shadow-md: 0 4px 6px -1px oklch(0 0 0 / 0.1), 0 2px 4px -2px oklch(0 0 0 / 0.1);` inside the `@theme` block. Tailwind v4 auto-generates the `shadow-md` utility. Token collision guard confirmed 0 collisions (v1 uses `.shadow-neo-*` utility classes, not `--shadow-*` CSS custom properties).

**2. aria-describedby strategy: error-priority single ref**

`describedBy = errorId ?? helperId`. Only one ID is referenced at any time. When error is truthy, errorId wins and helperId is not computed. When only helper is truthy (no error), helperId wins. When neither, `describedBy` is undefined and the attribute is omitted — avoids RESEARCH Pitfall 3 (orphan aria-describedby referencing non-existent element).

**3. hover:-translate-y-0.5 Tailwind v4 utility confirmed**

Used `hover:-translate-y-0.5` directly — Tailwind v4 generates `translateY(-0.125rem)` = -2px. No scoped style fallback needed. Build confirmed this generates valid CSS.

**4. TDD assessment: no unit-level tests written**

Per TDD directive for Plan 24-02: Card, Input, Badge are primarily presentational markup. Behavior-adding features (polymorphic as prop rendering, aria-describedby wiring, interactive tabindex) require DOM rendering to verify. Wave 3 Playwright tests (Plan 24-03) will cover:
- Input renders `<input>`, `<textarea>`, `<select>` per `as` prop
- `aria-invalid` present on Input with error prop
- `aria-describedby` references existing error element
- Card with `interactive=true` has `tabindex=0`
- Zero axe-core violations on /design-system page
