ASVS L1 surface for Card/Input/Badge:

- V5 Validation/Sanitization: Input.astro spreads {...rest} HTMLAttributes onto the polymorphic Tag — Astro escapes attribute values; any caller passing user-controlled value/placeholder/name strings is responsible for escaping their own data sources. Since this is a primitive imported by static .astro pages (design-system demo + Phase 28 contact form later), no live user input flows through Input.astro at build time. Risk: low.
- V3 Session: n/a — no session code in primitives.
- V4 Access Control: n/a — no auth in primitives.
- V13 Web Services: n/a — primitives make no fetch calls.
- V11 Business Logic: n/a — primitives are presentational.
- V14 Configuration: No env vars or runtime config consumed.

Specific accessibility-as-security concerns (relevant for COMP-07 in Plan 24-03):
- Input's aria-describedby MUST only be set when the referenced error element exists (RESEARCH Pitfall 3). Mismatch causes screen readers to announce nothing or error — an accessibility regression but not a security exposure.
- Card with interactive=true MUST set tabindex=0 so keyboard users can reach it; otherwise focus is unreachable (WCAG 2.1.1 Keyboard).

Block on: high severity findings. None identified — primitives have no auth, no input persistence, no secret handling.
