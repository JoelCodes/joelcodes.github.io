## Dev-Hidden Mechanism (IA-02)

This is an SEO/build concern, not visual, but it touches `SEO.astro` (a component).
Contract for the executor:

### SEO.astro — noindex prop

Add an optional `noindex?: boolean` prop (default `false`) to `SEO.astro`. When `true`:
- Render `<meta name="robots" content="noindex, nofollow" />` in `<head>`
- Do NOT alter `<link rel="canonical">` — the canonical stays valid even when noindexed

Both `/services/web` and `/areas/abbotsford` pass `noindex={true}` via `BaseLayout`'s
`<head>` slot (or directly via SEO props if BaseLayout exposes them through).

Implementation pattern (follows Phase 34 BaseLayout slot precedent):
```astro
<!-- In services/web.astro and areas/abbotsford.astro frontmatter / head slot -->
<BaseLayout title="..." description="...">
  <meta slot="head" name="robots" content="noindex, nofollow" />
  ...
</BaseLayout>
```

Alternatively, if `SEO.astro` gains the `noindex` prop: `<SEO noindex={true} ... />`.
The planner decides which wiring pattern; both are valid. The contract is: the rendered
`<head>` must contain `<meta name="robots" content="noindex, nofollow">` for both pages.

### astro.config.mjs — sitemap filter

Extend the existing `filter()` from Phase 38 (which excludes `/blog` and `/showcase`) to
also exclude `/services/` and `/areas/`:

```js
filter: (page) =>
  !page.includes('/blog') &&
  !page.includes('/showcase') &&
  !page.includes('/services/') &&
  !page.includes('/areas/'),
```

**Verification gate:** `npm run build && grep -r "services/web\|areas/abbotsford" dist/sitemap-*.xml`
must return zero results.

The `ProfessionalService` structured data must appear in the rendered `<head>` of the
Abbotsford page. This is a build-time static block — no runtime JS needed.

**Required schema (minimum):**
```json
{
  "@context": "https://schema.org",
  "@type": "ProfessionalService",
  "name": "Joel Shinness Solutions",
  "url": "https://joelshinness.com",
  "areaServed": "Abbotsford, BC",
  "serviceType": "Web Development",
  "provider": {
    "@type": "Person",
    "name": "Joel Shinness"
  }
}
```

**Implementation:** Inline `<script type="application/ld+json">` in the page's `<head>` slot
(via `BaseLayout`'s `<slot name="head" />`). Follow the same pattern as `SEO.astro`'s
existing `set:html={JSON.stringify(personSchema)}`. This JSON-LD must appear in
`npm run build` output even though the page is noindexed — search engines can still discover
and parse it from direct URL access.

**`areaServed` value:** `"Abbotsford, BC"` — verbatim per ROADMAP SC-3 and REQUIREMENTS PAGE-04.
