## Interaction Contracts

### Scroll-Spy (IA-04, CONTEXT D-01 through D-04)

**Implementation:** ~15 lines vanilla `IntersectionObserver` as `<script is:inline>` in `SiteHeader.astro`.

**Observed sections:** `#services` and `#about` only. No other sections.

**Active state:** `aria-current="location"` attribute set on the matching nav link. CSS hook:
```css
/* Add to SiteHeader.astro <style> block */
nav a[aria-current="location"] {
  color: var(--color-wl-accent);
}
/* Showcase link: build-time active state on /showcase */
nav a[aria-current="page"] {
  color: var(--color-wl-accent);
}
```

**Between-section behavior:** No link is active when neither `#services` nor `#about` is
in view (Hero, How-it-works, Proof, Final CTA, etc.). The nav only asserts what is true (CONTEXT D-03).

**rootMargin:** `-64px 0px 0px 0px` — compensates for the 64px sticky header so the section
is not counted "intersecting" while still hidden behind the header (RESEARCH pitfall 1).

**Progressive enhancement:** Without JS, nav links are all functional but carry no active state.

**Cross-page anchor (success criterion 3):** `/showcase` nav link uses `href="/#services"`.
The IntersectionObserver only fires when `#services` and `#about` exist in the DOM — on pages
other than `/`, no elements match `getElementById('services')`/`getElementById('about')`, so
the observer is never called and no false active state is set (RESEARCH pitfall 3).

**Showcase link build-time `aria-current`:** Add `const currentPath = Astro.url.pathname;`
to SiteHeader frontmatter. Render `aria-current="page"` on the Showcase `<a>` when
`currentPath === '/showcase'`. Same CSS rule as above covers it (CONTEXT D-04).

**Script placement:** `<script is:inline>` at the bottom of `<header>` in `SiteHeader.astro`.
