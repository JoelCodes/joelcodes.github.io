## Spacing Scale

Base: 8-point scale (multiples of 4px). All spacing values in new `wl/` components
must derive from this scale or be Figma-extracted exact values.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps within buttons, tight inline spacing |
| sm | 8px | Compact element spacing, internal component padding |
| md | 16px | Default element spacing |
| lg | 24px | Section padding within components |
| xl | 32px | Layout gaps between component groups |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

**Exceptions (Figma-extracted exact values that don't land on 8pt grid):**

| Context | Value | Source |
|---------|-------|--------|
| CTAButton `solid` / `small` vertical padding | 9px | `SiteHeader.astro` inline spec (Phase 34 approved); verify vs Figma node `39:15` / `39:30` |
| CTAButton `solid` / `small` horizontal padding | 17px | Same source |
| CTAButton border-radius | 10px | Same source |
| CTAButton min-height | 44px | WCAG 2.5.5 touch target — non-negotiable |
| Header gap between nav items | 26px | `SiteHeader.astro` line 29 |
| Header mobile gap | 18px | `SiteHeader.astro` line 58 |

**FIDELITY-GAPs (must be Figma-extracted before implementation):**

- Ghost button padding, border-width, border-radius (node `39:31` or `39:15`)
- Ghost-on-dark button padding, border-width (dark mockup `117:103`)
- Eyebrow: margin/gap below eyebrow text (if specced on `36:5`)
- Tag: padding, border-radius (node on `36:5`)

### On-dark variant color contract (D-09, D-10)

On-dark variants (`ghost-on-dark`, `Eyebrow onDark`) appear on ink-colored surface
sections (e.g., landing page hero strip, final CTA strip). These surfaces exist in
BOTH light and dark mode — their components must look stable regardless of the global
`.dark` class.

**Rule:** On-dark variants use non-flippable values — either a literal hex or a
`:root`-scoped custom property. They MUST NOT use `var(--color-wl-on-ink)` or any
other flippable `--wl-*` token.

**Precedent:** Footer-local `:root` properties (`--wl-footer-*`) established this
pattern in Phase 34. Phase 35 extends it for the on-dark component variants.

**FIDELITY-GAPs — must be Figma-extracted from dark mockup `117:103` before implementation:**

| Component | Value Needed | Why Non-Flippable |
|-----------|-------------|-------------------|
| `CTAButton` ghost-on-dark text color | exact hex | Ink strip section in both modes |
| `CTAButton` ghost-on-dark border color | exact hex | Same |
| `CTAButton` ghost-on-dark hover state | exact hex or opacity | Same |
| `Eyebrow` onDark text color | exact hex | Same |

If dark mockup `117:103` shows no visual change for ink-strip components between
light-mode and dark-mode views, document as "stable — confirmed non-flip" with
node ID reference.

## Interaction Contracts

### Focus States (All Interactive Elements)

Pattern from Phase 34 chrome (`SiteHeader.astro` — all interactive links):

```
focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-wl-accent
```

Apply to: CTAButton, LinkCard (full card), Breadcrumb links.
Do NOT use for non-interactive elements (Eyebrow, Tag, Callout, Step, ServiceCard).

**On-dark focus ring caveat:** The flippable `--wl-accent` token in dark mode is
`#4FB3B8`. On always-dark ink surfaces (`#12333B`), verify AA contrast for the
focus ring. If it fails, use a non-flippable literal (e.g., `#4FB3B8` directly)
as a `:root` custom property per the footer-local-value precedent.

### Hover States (Claude's Discretion — derived from chrome convention)

Apply hover treatments only where Figma static frames imply interactivity.
Default derivation from chrome convention unless Figma extraction reveals otherwise:

| Component | Hover Treatment | Source |
|-----------|----------------|--------|
| CTAButton all variants | FIDELITY-GAP — flag for Figma extraction | |
| LinkCard | FIDELITY-GAP — flag for Figma extraction | |
| Breadcrumb links | `hover:text-wl-accent` | Chrome convention (`SiteHeader.astro` nav links) |

### Animation / Motion

**Phase 35 primitives are STATIC — zero client JS, zero CSS transitions** (RESEARCH.md
"Standard Stack" and CONTEXT.md "Zero client JS" established pattern). Interactivity
(expand/collapse, accordion) belongs to Phase 36.

Exception: `prefers-reduced-motion` already handled at the HTML level in `global.css`
(`scroll-behavior: auto`). No component-level motion is introduced.
