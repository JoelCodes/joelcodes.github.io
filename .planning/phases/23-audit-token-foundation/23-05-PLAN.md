    Step 2 — Create the parent frame. Use Pencil MCP batch_design to insert the frame:
    - name: `_Tokens & Foundations`
    - x: from Step 1
    - y: from Step 1
    - width: 1440 (matches Crito page widths for screenshot consistency per RESEARCH Pitfall 4)
    - layout: auto-layout vertical (flex column) with token-driven padding/gap referencing space-semantic-* aliases
    - background: color-semantic-bg-page (or bg-surface for contrast)

    Step 3 — Populate sections. Order (Claude's Discretion per CONTEXT): color → typography → spacing → radii → dark-mode omission note. Each section is a child frame of TOKEN_FRAME_ID with a heading text node + token rows. batch_design caps at ~25 ops per call per RESEARCH; chunk by section if needed.

    Section A — Colors (under heading "Colors"):
    For each color token (primitive + semantic) in PEN-INVENTORY.md `## Tokens Written` logs:
    - Insert a horizontal row frame with auto-layout
    - Child 1: rectangle 48x48 with fill = the token's value (use semantic alias if the token IS a semantic alias; use primitive if it's a primitive)
    - Child 2: text node with the token's name (font: type-semantic-body, color: text-primary)
    - Child 3: text node with the token's literal value (font: type-semantic-body-sm or caption, color: text-secondary or primary)
    For semantic aliases that use DESCRIPTION-FALLBACK aliasing: add a fourth text node "→ <primitive-name>" so the alias relationship is visible.

    Section B — Typography (under heading "Typography"):
    For each typography semantic alias (display, heading-1..6, body, body-sm, caption, button, prose-paragraph, prose-link, prose-list, plus prose-inline-code IF written):
    - Insert a vertical row frame
    - Child 1: text node sample reading "The quick brown fox jumps over the lazy dog" rendered with the typography token's family + size + weight + line-height
    - Child 2: text node with the token's name + composite values (family / size / weight / lh) in a small caption style

    Section C — Spacing (under heading "Spacing Scale"):
    For each spacing primitive (space-primitive-*) — present primitives because semantic spacing aliases are role names, not visible widths:
    - Insert a horizontal row frame
    - Child 1: rectangle of width = the spacing value (e.g., 24px wide for space-primitive-24), height = 16px, fill = accent
    - Child 2: text label "<token-name> = <value>px"
    Also render a small table of semantic spacing aliases mapping to primitives (e.g., "section-y → primitive-96").

    Section D — Radii (under heading "Radius"):
    For each radius primitive:
    - Insert a row with a 64x64 filled rectangle using the radius value as cornerRadius
    - Adjacent text node: "<token-name> = <value>"
    Plus a semantic-alias-to-primitive mapping table (card → md, button → sm, etc.).

    Section E — Dark-Mode Omission Note (under heading "Dark Mode — Deferred per D-01 / TOKEN-07"):
    A text block stating:
    "Dark-mode token slots are intentionally omitted in v2.0 (CONTEXT D-01, TOKEN-07). No @light,@dark variable syntax exists in this file. Future milestone will design dark values from scratch. Do not retro-add dark slots in any v2.0 phase."
    Style: small caption font, low-contrast color to de-emphasize relative to live tokens but still legible.

    Step 4 — Structural QA. Call Pencil MCP snapshot_layout with rootId=TOKEN_FRAME_ID and problemsOnly=true. Expected response: zero clipping issues, zero overlap issues. If any returned, fix via additional batch_design calls (adjust auto-layout padding/gap, wrap clipping children, reorder children to remove overlap). Re-run snapshot_layout until clean.

    Step 5 — Forbidden operations in this task:
    - NEVER use batch_design to update / delete / move any node that is NOT a child of TOKEN_FRAME_ID (Pitfall 5 / VAL-23-05 enforcement — existing Crito frames stay untouched).
    - NEVER use replace_all_matching_properties (reserved for Phase 32 fidelity sweep per RESEARCH).
    - NEVER use raw hex values inside the new frame — every fill must reference a semantic alias by name (D-14 / TOKEN-01 enforcement — the reference frame is itself an example of the rule). The ONLY exception is the swatch rectangles in Section A whose fill is the token's literal value because the swatch IS the token being demonstrated; that's documentation, not a violation. All non-swatch fills (frame backgrounds, text colors) reference semantic aliases.
