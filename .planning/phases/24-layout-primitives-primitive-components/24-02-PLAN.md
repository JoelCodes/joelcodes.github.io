<objective>
Build `Primitive / Button` inside `_Components / Primitives` (id from plan 24-01) as the first primitive component. Ship a **bounded variant matrix**: only the Crito-source-depicted purposes (D-24) plus the D-22 compositional minimum forward set (`:focus` for Phase 27 keyboard nav, `:hover` for Phase 25 Header CTA pointer state) — each forward-added variant carries an `OPEN-24-NN` flag declaring its consumer phase.

**Two probe checkpoints land first** (RESEARCH Pattern 5 + Pitfalls 1, 2):
- **Component shape probe (Q1):** Verify Pencil schema 2.13's component declaration shape (frame-as-component Pattern A vs distinct component node type Pattern B) by inserting a minimum-viable Probe Button and inspecting its `batch_get` result. Document outcome before building variant matrix.
- **Slot mechanics probe (Q2 + Q3):** Verify slot-typing payload syntax (`slot: [<id>]` array at insert time) AND empty-slot auto-collapse behavior (`enabled: false` produces a true zero-bounding-box collapse vs slot still occupying width/height). Pause for user confirmation on outcome.

Each variant cell built thereafter uses LITERAL values in `batch_design` payloads (OPEN-23-13 dual-track) with corresponding rows in PEN-INVENTORY.md `## Variant Evidence (Phase 24)` binding each literal to its semantic token name.

**Purpose:** Establishes the variant-cell-as-frame pattern (Pattern A) that plans 24-03 and 24-04 will reuse. Probes resolve the two highest-confidence-but-unverified assumptions (component shape + slot collapse) that downstream plans depend on. Forward variants are gated to compositional-minimum (D-22) — no v1.4-style over-engineering.

**Output:** Button variant cells inside `_Components / Primitives`, audit-trail rows, OPEN-24-NN flags, probe outcomes documented for Phase 25 consumers.
</objective>
