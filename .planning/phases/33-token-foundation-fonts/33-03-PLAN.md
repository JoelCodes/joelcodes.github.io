  <behavior>
    The script exposes pure functions `hexToRgb`, `linearize`, `relativeLuminance`, and
    `contrastRatio(hex1, hex2)` implementing the W3C WCAG 2.x relative-luminance formula. It defines
    a `PAIRS` matrix of `[foreground, background, label, threshold]` rows covering every mockup-observed
    text-on-background combination in BOTH light and dark themes (per the UI-SPEC pair matrix, seeded
    with 33-01's extracted hexes). It loops the matrix, logs `PASS|FAIL {label}: {ratio}:1 (threshold {N}:1)`,
    and `process.exit(failed ? 1 : 0)`.

    Testable cases (RED first):
    - `contrastRatio('#000000', '#FFFFFF')` -> ~21.0 (W3C reference: exactly 21:1).
    - `contrastRatio('#FFFFFF', '#FFFFFF')` -> 1.0 (identical colors).
    - `contrastRatio(A, B)` === `contrastRatio(B, A)` (order-independent).
    - `relativeLuminance` of `#FFFFFF` -> 1.0; of `#000000` -> 0.0.
    - A known mid-tone pair (e.g. `#767676` on `#FFFFFF`) -> ~4.54:1 (the canonical AA boundary grey).

    The known EXPECTED FAIL: accent-soft (33-01 extracted hex) on paper at 4.5:1 for small text must
    report FAIL. The remedy is a companion `--wl-accent-soft-text`: derive it by minimally darkening
    accent-soft at the SAME hue (reduce OKLCH lightness in small steps) until `contrastRatio(companion, paper) >= 4.5`.
    Document the before/after hex + ratios. Once the companion passes, the accent-soft-TEXT row passes
    while the decorative accent-soft-large row (3:1) may still be listed. The script's final exit code
    must be 0 (all TEXT-use pairs pass, companions in place).
  </behavior>
