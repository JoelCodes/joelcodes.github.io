<threat_model>
**Surface:** One new external redirect (`/contact` → Calendly).
**ASVS L1 review:**
- **Open-redirect (V5.1 / redirect abuse):** NOT applicable. All redirect destinations are hardcoded string literals in `astro.config.mjs` (`/showcase`, `/`, and the fixed Calendly URL). No destination is derived from user input, query params, or path segments — there is no untrusted-input → redirect flow. The Calendly host is a trusted, known destination already used by every Book-a-call CTA (`BOOKING_URL`).
- **Injection:** None. Redirect map is static config evaluated at build time; no runtime request handling (static GitHub Pages, no server).
- **Info exposure:** Redirect stubs carry `noindex`; no secrets are emitted.
**Conclusion:** No high/medium findings. This change does not introduce an exploitable redirect vector.
</threat_model>
